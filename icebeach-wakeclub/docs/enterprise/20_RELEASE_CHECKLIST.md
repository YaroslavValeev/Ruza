# Release checklist: controlled pilot

## Цель
Подтвердить, что система готова к dry run и первой реальной смене.

## До релиза
- [ ] Все открытые секреты ротированы и убраны из рабочих заметок
- [ ] Staff login согласован и задокументирован
- [ ] `docs/enterprise/00_README_ГОВЕРНАНС.md` отражает целевой cycle
- [ ] `docs/enterprise/05_SOP_БРОНЬ_ЧЕКИН_ОЧЕРЕДЬ.md` отражает статусы `confirmed -> arrived -> ready -> in_progress -> done`
- [ ] docs/enterprise/21_RUNBOOK_РЕАЛЬНАЯ_СМЕНА.md выдан staff как one-page инструкция на pilot day
- [ ] `docs/enterprise/08_SOP_БЕЗОПАСНОСТЬ_ОБОРУДОВАНИЕ.md` и чек-листы синхронизированы
- [ ] `docs/enterprise/19_CHANGELOG.md` содержит запись о пилотном выпуске

## Перед dry run
- [ ] Есть дата пилота и ответственный staff
- [ ] Есть тестовые клиенты или сухой сценарий
- [ ] Есть доступ к Google Sheets и dashboard
- [ ] Есть актуальные роли `admin`, `operator`, `pilot`
- [ ] Есть понятные правила `late`, `no_show`, `cancelled`
- [ ] Есть список контактов на случай инцидента

## Перед первой реальной сменой
- [ ] Operator может создать бронь и довести её до `ready`
- [ ] Pilot может увидеть очередь и закрыть `in_progress -> done`
- [ ] Есть правило, что отмена после старта не используется
- [ ] Есть fallback-процедура при несоответствии статуса и реальности
- [ ] Есть человек, который принимает go/no-go решение на месте

## Release gate
- [ ] Нет блокеров по секретам
- [ ] Нет блокеров по доступам staff
- [ ] Нет блокеров по статусному циклу
- [ ] Нет блокеров по runbook
- [ ] Нет блокеров по чек-листу открытия и закрытия дня

## Post-release
- [ ] Собрать короткий ретро-бриф
- [ ] Зафиксировать расхождения в `19_CHANGELOG.md`
- [ ] Обновить SOP, если какой-то шаг был неочевиден
